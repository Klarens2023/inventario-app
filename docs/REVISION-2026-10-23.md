## Para revisar juntos mañana

1. **Probar en el navegador** con `npm run build && npm start` (o en el Preview de Vercel):
   - iniciar sesión, navegar por los módulos e **imprimir** un movimiento TIC y un acta de repuestos (la impresión cambió);
   - poner mal la contraseña: el mensaje sigue siendo "Usuario o contraseña incorrectos".
2. **Decidir el despliegue.** Orden recomendado:
   1. commit y push de la rama, y Preview en Vercel;
   2. correr `scripts/migrate-add-login-ip.js` contra producción. Puede ir antes o después del despliegue: sin la tabla, el login funciona igual, solo que sin límite por IP;
   3. crear en Vercel (Production) la variable `LOGIN_IPS_CONFIANZA=190.242.100.248/29`, para que la oficina no se bloquee por IP;
   4. Sync fork y verificación en producción.
3. **Costo de la CSP con nonce:** las páginas dejan de ser estáticas y se generan en cada petición. Para una app interna el impacto es pequeño, pero conviene mirar los tiempos en Vercel después de desplegar. Para revertir solo esto: `middleware.ts`, `next.config.js` y `app/layout.tsx`.
4. **App móvil SDK 58:** si se aprueba, se hace un build EAS de prueba (consume cupo de builds) y se instala en un teléfono antes de reemplazar el APK actual.
